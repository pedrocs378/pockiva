# PED-37 Desktop Emulator Shell Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the keyboard-first Tauri desktop shell that opens a local ROM, exposes explicit lifecycle and failure states, renders bounded raw RGBA frames from a replaceable core mock, and persists a complete configurable keyboard mapping.

**Architecture:** React talks only to a typed Tauri adapter. Tauri commands serialize ROM lifecycle and full keyboard snapshots onto one native worker; a small JSON `Channel<RuntimeEvent>` carries control snapshots, while a separate `Channel<Response>` sends `InvokeResponseBody::Raw` packets that arrive as `ArrayBuffer`. Each binary packet has a stable 12-byte little-endian header followed by exactly `160 x 144 x 4` RGBA bytes, and an acknowledgement command bounds the video path to one frame in flight plus one latest pending frame. The worker depends on an injected `CoreFactory`; PED-37 keeps a deterministic contract mock wired in production only until PED-39 replaces the registration with the real `SystemClock` + `GameBoy` factory.

**Tech Stack:** Node.js 24.20.0, pnpm, TypeScript 7, React 19, Vite 8, Vitest 4, Testing Library, Tailwind CSS 4, shadcn/ui, Zod 4, Tauri 2.11.5, `@tauri-apps/api` 2.11.1, `tauri-plugin-dialog`, `tauri-plugin-store`, Rust stable, `gb-core`

**Spec:** `docs/superpowers/specs/2026-08-27-game-boy-emulator-design.md`

## Global Constraints

- Target macOS Apple Silicon and Windows x64.
- Keep `gb-core` independent of Tauri, React, filesystem, network, and platform-audio APIs; do not change any public type in `crates/gb-core/src/contracts/**` in PED-37.
- Accept only the frozen `EmulatorCore`, `CoreError`, `Frame`, `Button`, `InputSourceId`, `JoypadState`, `CartridgeMetadata`, `MapperKind`, `CompatibilityMode`, `SCREEN_WIDTH`, and `SCREEN_HEIGHT` contracts.
- Do not implement a CPU, PPU, APU, cartridge mapper, battery-save persistence, remote-controller server, QR flow, WebSocket, or mobile networking in this issue. Battery-save loading, atomic checkpoints, close/shutdown flush, and corrupt-save preservation are explicitly owned by PED-40.
- Do not import desktop source from `apps/remote-controller` and do not modify `packages/protocol`, `crates/gb-network`, or the controller-reserved `apps/desktop/src-tauri/src/remote/**` path.
- Use Node.js `24.20.0`, pnpm, exact JavaScript dependency versions, TypeScript, Biome, Rust stable, workspace lints, and the committed lockfiles.
- Open the native dialog with `@tauri-apps/plugin-dialog`; it returns a path only. Read ROM bytes in the Rust worker, never in React and never through a browser filesystem API.
- Store keyboard settings through `tauri-plugin-store` in `settings.json`, which resolves beneath the application-data directory; do not use `localStorage` or write beside the ROM.
- Use Tauri commands for request/response operations, one `Channel<RuntimeEvent>` containing only small typed control snapshots, and one `Channel<Response>` containing only `InvokeResponseBody::Raw` frame packets. Do not put `Vec<u8>` inside a Serde/JSON event, and do not use global Tauri events, PNG encoding, base64 encoding, data URLs, or an unbounded frame queue.
- Encode every frame packet as exactly `92_172` bytes: sequence at bytes `0..8` as `u64` little-endian, width at `8..10` as `u16` little-endian, height at `10..12` as `u16` little-endian, and `92_160` RGBA bytes at `12..92_172`. The frontend accepts an `ArrayBuffer`, validates all header fields and total length, and acknowledges only after `putImageData`.
- Keep one frame in flight and at most one latest pending frame. React acknowledges a frame only after `putImageData`; newer pending frames replace older pending frames.
- Use physical `KeyboardEvent.code` values. Ignore gameplay input while a text/editing control or the mapping dialog owns the keyboard, suppress duplicate `keydown` events, and clear the keyboard source on `keyup`, blur, visibility loss, ROM close, and application shutdown.
- Reserve `InputSourceId::new(1)` for the keyboard in the desktop runtime. PED-39 owns allocation and cleanup of remote input sources.
- Test with synthetic bytes created during tests. Never commit, download, log, or expose commercial ROM contents or absolute ROM paths to the UI.
- Keep the remote-controller status as an inert “off” presentation; PED-39 owns real session controls.
- Keep `ContractMockCoreFactory` registered in production for PED-37. PED-39 owns the sole desktop factory swap to the real PED-35 `GameBoy` implementation with a platform `SystemClock`; PED-35 does not edit `apps/desktop`.
- `Cargo.lock` is coordinator-owned during parallel lanes. PED-37 may request its refresh after Rust dependency changes but must never stage or commit it. `pnpm-lock.yaml` is PED-37 lane-owned because no other phase-one lane changes desktop JavaScript dependencies.
